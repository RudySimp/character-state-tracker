# Character State Tracker

Модуль для Foundry Virtual Tabletop v14, который хранит физическое, ментальное, эмоциональное состояние и потребности персонажа в одном профиле JournalEntry.

## Установка

В Foundry откройте **Add-on Modules → Install Module** и вставьте:

`https://github.com/RudySimp/character-state-tracker/releases/latest/download/module.json`

После активации модуль запускается кнопкой в каталоге журналов или клавишей `Ctrl+C`. Все изменения профиля выполняет GM; игроки получают только доступ, который разрешён правами Journal.

## Модель данных

- Один профиль = один JournalEntry.
- Источник истины — `flags.character-state-tracker.characterStateTracker`.
- Страницы Summary, Physical, Mental, Needs и History — производные и восстанавливаются кнопкой Repair.
- Страница GM Notes не перезаписывается генератором.
- Старые данные из `flags.world.characterStateTracker` читаются без изменения; явная миграция копирует проверенные данные в namespace модуля.
- Резервная копия JSON проходит проверку схемы и ограничение размера 10 MiB.

## Возможности

Карта частей тела, локальная боль, активные и архивные травмы, числовые шкалы с шагом, ментальные и эмоциональные оси, потребности, температура, custom states, история изменений, фильтрация истории, импорт/экспорт, архивирование профилей, диагностика и локальные звуковые cues.

## Разработка и проверки

```text
npm test
npm run validate
npm run build
```

Сборка создаёт `dist/character-state-tracker.zip`, `dist/module.json` и `dist/SHA256SUMS.txt`. ZIP не содержит внешнюю wrapper-папку и использует POSIX-разделители.

Подробная карта ресурсов находится в [docs/ASSET_MAP.md](docs/ASSET_MAP.md), история релиза — в [RELEASE_NOTES_1.0.0.md](RELEASE_NOTES_1.0.0.md).

## Разделы интерфейса

Физическое состояние использует интерактивную карту тела, общую и локальную боль, заметки и карточки травм. Ментальный и душевный разделы имеют отдельные шкалы, conditions и пользовательские оси. Потребности поддерживают стандартные и custom значения; температура хранит текущую величину и индивидуальные границы нормы; Custom States не добавляют RPG-механику и служат описанием состояния.

Сводка показывает ленту статусов и проблемы, История — события с пользователем, причиной, фильтрами и постраничной загрузкой. Настройки объединяют диагностику, repair pages, восстановление GM Notes, backup и миграцию.

## Безопасность данных

Изменения проходят через одну очередь на JournalEntry, проверку ревизии, нормализацию и валидацию. Future schema доступна только для чтения. Генерируемые страницы помечены отдельным flag; пользовательская страница GM Notes не перезаписывается. Внешние изменения другого GM обновляют окно только при отсутствии локального черновика.

## Обновление и ручная установка

Для обновления установите новый релиз поверх предыдущего и сохраните резервную копию. При ручной установке скачайте ZIP релиза и распакуйте его как содержимое директории модуля Foundry, чтобы `module.json` лежал в корне. После обновления проверьте Journal pages и выполните Repair только при необходимости.

## Устранение проблем

Если профиль помечен как legacy, сначала экспортируйте backup, затем используйте явную кнопку миграции. Если страница отсутствует или дублируется, используйте Repair pages. Диагностика показывает future schema, отсутствующие managed pages, дубли травм и историю большого размера. Звуки по умолчанию выключены и проигрываются только на значимых переходах.
